# 进入市场策略

状态：2026-09-27 初稿（基于 [竞争格局分析](competitive-landscape.md) 推导）。

本文件是策略文档，不是执行任务卡。具体实施步骤拆分到对应阶段再落成任务。

## 1. 竞争分析的核心结论

竞品对比揭示了三件事：

1. **功能组合是市场空白**。Creem-first + 积分账本 + 获客三件套 + 单色品牌系统 + Better Auth + Neon 可分支 + 上游 git merge——这七个点没有人同时做。最近的竞品（MuseMVP $99、MkSaaS）各覆盖了子集，但都不完整。

2. **弱点也是真实的**。零知名度、仅 Creem（无 Stripe 适配器）、v1 无多租户、中文文档天然限定了受众。不是"再改改就能和 ShipFast 正面打"的局面。

3. **市场不等人**。ShipFast 8400+ 买家、MakerKit 维护 3 年、MuseMVP 走多支付网关路线。窗口期有限——如果 Creem 生态成长起来，Creem-first 这个定位很快会有人填。

**策略方向**：不是和 ShipFast 比谁更快，不是和 MakerKit 比谁更企业。**守住"出海 AI SaaS 完整底盘"的定位，用功能深度换早期信任，用内容营销换分发渠道。**

## 2. 目标用户画像（ICP）

### 首要 ICP：中国独立开发者做 AI SaaS 出海

- 技术栈偏好 Next.js + TypeScript
- 需要海外收款但没有公司主体（Creem MoR 是刚需）
- 产品形态是 AI wrapper / AI 工具（积分计费是刚需）
- 英语可以读写但更习惯中文文档
- 预算敏感但愿意为省时间付费（$99–$199 是可接受范围）
- 活跃在即刻 / 知乎 / Twitter / Product Hunt

### 次要 ICP：任何想要 MoR 支付的独立开发者

- 不限于中国，任何没有海外公司主体的独立开发者
- 被 Stripe 要求公司主体劝退过
- 需要"一个模板搞定全部基础设施"
- 对 Creem 已有认知

### 反 ICP（不服务）

- **需要多租户的团队/企业**（v1 明确不做，不要在这类用户上浪费营销）
- **已有 Stripe 账号和海外主体的开发者**（他们应该用 ShipFast/MakerKit，除非被积分和获客吸引）
- **非 AI SaaS 场景**（纯订阅制 SaaS 不需要积分系统，我们的优势用不上）

## 3. 定价策略

### 定价原则

- 功能比 $199 档的 ShipFast 多（积分、获客、设计系统、i18n），但信任度为零
- 不能高于 $349 的 MakerKit（多租户比我们完整，维护历史长 3 年）
- 不能低于 $49 的 ZapStart（功能远超那个档位，低价反而信号"质量差"）

### 建议方案

| 阶段 | 价格 | 目标 |
|------|------|------|
| **上线首月（早鸟）** | **$99** | 获取 20–50 个付费用户，积累 testimonials 和案例 |
| **正常售价** | **$169** | 稳定跑几个月，验证转化率和用户质量 |
| **后续调整** | $149–$199 | 根据 feedback 和功能增量（Stripe 适配器、多租户）上调 |

### 为什么不是 $199+？

ShipFast 的 $199 靠的是 8400+ 用户、135K 推特的信任背书。我们没有。$99 的早鸟价承认了这一差距，同时给出一个"趁现在便宜"的行动理由。提到 $169 后仍然比 ShipFast 便宜，功能更多——这对理性买家是明确的性价比信号。

### 为什么不是 $49？

ZapStart $49 是"基础功能骨架"的定位。我们的功能深度（积分账本、获客、品牌系统）远超那个档位。低到 $49 会吸引只想便宜、不看重功能深度的用户——他们会是售后负担（"为什么没 Stripe？为什么没多租户？"）。

## 4. 分发渠道

没有个人品牌（不像 Marc Lou），分发必须靠**渠道合作 + 内容营销**。

### 渠道 1：Creem 合作伙伴

**这是最高杠杆的分发路径。** Creem 作为 MoR 平台，天然希望有更多模板/教程降低他们的接入门槛。我们的模板让开发者"不用写 Creem 集成"——这对 Creem 的获客有利。

具体做法：
- 联系 Creem 的开发者关系 / partnership 团队
- 争取进入 Creem 官方文档的 "Starter Kits" / "Templates" 区块
- 如果 Creem 有 affiliate 计划，加入
- 写 Creem 接入教程，被 Creem 官方转发

### 渠道 2：内容营销（出海教程）

**不卖模板，卖知识。** 模板是知识付费的自然延伸。

内容主线：
- "独立开发者出海 SaaS 从 0 到 1"系列（技术选型、收款、税务、获客）
- "不需要海外公司也能收美金——Creem 实战指南"
- "AI SaaS 的积分计费怎么设计——从账本到原子扣减"
- 每篇结尾自然提及模板，"不想从零写？这里有完整实现"

分发平台优先级：知乎 > 即刻 > Twitter/X > 小红书（技术内容更适合前两个）

### 渠道 3：Product Hunt

ShipFast 的早期 traction 很大程度上来自 Product Hunt。我们需要：
- 准备好的 PH 上线素材（首图、描述、Maker 故事）
- 在 PH 活跃社区预热 2–4 周
- 选一个周二/周三/周四上线（PH 流量最大的日子）
- 标题突出差异化："Creem-first Next.js SaaS Kit — built-in credits, acquisition & branding"

### 渠道 4：开源引流

模板本身是专有授权，但可以开源一些独立组件：
- `brand-css` 推导逻辑 → 独立 npm 包 / 博文（"一个 hex 换整套品牌色"）
- 积分账本设计 → 架构博文
- 获客归因系统 → 独立指南

这些内容本身有价值，同时把读者引向完整模板。

## 5. 上线前必须补齐的缺口

基于竞争分析，以下是上线前**必须做**和**建议做**的区别：

### 阻塞上线（必须）

| 缺口 | 当前状态 | 行动 |
|------|----------|------|
| **Stripe 适配器态度** | plan.md 写"v1 不做"，competitive-landscape 写"劣势" | **不改实现，但改说法**：在产品页/README 写明路线图——"Stripe 适配器计划中，时间线取决于需求量。Creem 已覆盖 MoR 场景，如果你需要 Stripe 请告诉我们"。把"没有"变成"计划中"。 |
| **Creem 审核指南** | 无 | **写一篇买家文档**：如何准备 Creem 审核（网站需要什么页面、产品描述怎么写、常见被拒原因）。这是降低买家"卡在审核"风险的最直接方法。 |
| **演示站** | sass.linonward.com | 确保演示站能完整走通：注册 → 看定价 → 模拟付款 → 积分到账 → 调 AI → 扣积分。买家先看到"这东西能跑"再决定买。 |
| **买家上手时间是否 ≤ 1 天** | plan.md 的验收标准 | **实际测一次**：找一个没用过本模板的人，从 fork 开始计时，看能不能在 1 天内完成全流程。差距就是文档改进清单。 |

### 上线前建议（不阻塞，但强烈建议）

| 缺口 | 行动 |
|------|------|
| **英文版文档** | 至少 README、UPGRADING、design.md 需要英文版。当前中文文档限定了 ICP 到中国开发者，英文化打开次要 ICP（全球 MoR 需求的独立开发者）。**工作量评估后决定是否 v1 做。** |
| **买家 testimonials** | 找 2–3 个早期用户（可以免费给），收集真实使用反馈和推荐语。上线时没有 social proof 是硬伤。 |
| **竞品对比页** | 在模板落地页加一页"Compare"——不是攻击竞品，是列出"你有这个需求 → 我们有，他们没有"的客观表。买家自己做竞品对比时，这一页就是他们的 cheat sheet。 |

## 6. 消息框架（Messaging）

### 一句话定位

> **The complete operating system for your AI SaaS.** Payments handled by Creem (no company entity needed). Usage billing via built-in credit ledger. User acquisition tools included. One hex code rebrands the entire site.

### 三大卖点（按买家决策顺序）

1. **"今天 fork，明天收钱"**——Creem MoR 让你不需要海外公司就能收美金。这是 出海开发者的第一痛点。
2. **"AI 调用按次收费，不用自己写"**——积分账本、预扣/退回、幂等 webhook，全部内置。这是 AI SaaS 的基础设施，多数模板没有。
3. **"不只是启动，是持续运营"**——渠道归因、候补名单、邀请奖励。别人卖的是 Day 1，我们卖的是 Day 1–30。

### 对标说法（买家问"和 ShipFast 有什么区别？"）

> ShipFast 帮你更快启动。我们帮你更快启动**并且**更快开始赚钱——积分计费让你第一天就能对 AI 调用收费，Creem 让你不需要海外公司就能收美金。如果你只做订阅制 SaaS、已经有 Stripe 账号，ShipFast 可能更适合你。如果你是 AI SaaS、需要用量计费、没有海外主体——我们是唯一的选择。

## 7. 风险与缓解

| 风险 | 概率 | 缓解 |
|------|------|------|
| **Creem 审核卡住买家** | 高 | Creem 审核指南文档 + 演示站作为"审核用参考" |
| **Creem 服务中断/政策变更** | 低 | 留 PaymentProvider 接口（已做）；公开 Stripe 路线图 |
| **大厂/知名模板跟进 Creem** | 中 | 快速积累用户和 testimonials，用先发优势 + 功能深度建护城河 |
| **中国开发者市场太小** | 中 | 英文化文档打开次要 ICP；内容营销不限于中文 |
| **首次用户体验差、退款多** | 中 | 实际测"fork 到上线 ≤ 1 天"、写清楚 onboarding checklist |
| **模板被 pirates 分发** | 中 | EULA 已覆盖法律层面；技术上 v1 不做 DRM。靠更新频率和 upstream merge 能力让正版买家持续获得价值 |

## 8. 不做的事

- **不和 ShipFast 打价格战**。他们在 $199 有 8400+ 用户，我们在 $99 有零。价格战我们只会亏更多。
- **不追求"所有人都能用的模板"**。ICP 窄是好事——功能深度来自聚焦，不是泛化。
- **不做付费广告（v1）**。没有 conversion data 之前，广告预算 = 烧钱。先靠内容营销和渠道合作积累数据。
- **不在 Product Hunt 之前做大规模宣传**。PH 是信任放大器，但前提是已经有 demo、有 testimonials、有文档——先准备这些。
- **不承诺"终身更新"**。MakerKit 可以承诺因为维护了 3 年。我们可以在早鸟期承诺 1 年免费更新，后续定价再调整。

## 9. 时间线建议

| 阶段 | 时间 | 目标 |
|------|------|------|
| **准备期**（当前–上线前） | 2–4 周 | 补齐阻塞缺口（审核指南、演示站、上手时间验证）、准备内容物料 |
| **早鸟期**（上线首月） | 4 周 | $99 早鸟价，目标 20–50 付费用户，收集反馈和 testimonials |
| **稳定期**（第 2–3 月） | 8 周 | 提价到 $169，持续内容营销，推进 Creem 合作关系 |
| **评估期**（第 4 月） | — | 用真实数据重新评估：定价是否合适、ICP 是否准确、Stripe 适配器是否该提上日程 |

## 10. 与现有阶段的关系

本策略不影响已完成的阶段 1–14。具体执行拆入后续阶段：

- 阻塞缺口（审核指南、演示站打磨、上手时间验证）→ 入 **阶段 15（上线准备）**
- 内容营销物料（博文、教程、PH 素材）→ 入 **阶段 16（内容与分发）**
- Stripe 适配器 → 保持"v1 不做"，但公开路线图
- 英文化文档 → 评估后决定是否入 v1 范围

策略本身随市场反馈持续修正，不设死日期。
