## 1. 竞争分析的核心结论

竞品对比揭示了三件事：

1. **功能组合少见，但这是抽查结论，不是市场结论。** Creem-first + 积分账本 + 获客三件套 + 单色品牌系统 + Better Auth + Neon 可分支 —— 这个组合在我们 2026-09-26 抽查过的产品里没有同时具备的（范围与方法见竞争分析文档；`上游 git merge` 一项当时列为已具备，实为待兑现，见下）。最近的竞品（MuseMVP $99、MkSaaS）各覆盖了子集。「少见」是可以写进产品页的说法，**「没人做」「唯一」不是** —— 抽查覆盖不到的产品、上架后新出的产品都可能推翻它。

2. **弱点也是真实的**。零知名度、无多租户、中文文档天然限定了受众，三个支付适配器（Creem / Stripe / Lemon Squeezy）也都还**没按买家流程在真实测试环境验证过**。不是"再改改就能和 ShipFast 正面打"的局面。

3. **市场不等人**。ShipFast 8400+ 买家、MakerKit 维护 3 年、MuseMVP 走多支付网关路线。窗口期有限——如果 Creem 生态成长起来，Creem-first 这个定位很快会有人填。

**策略方向**：不是和 ShipFast 比谁更快，不是和 MakerKit 比谁更企业。**守住"出海 AI SaaS 完整底盘"的定位，用功能深度换早期信任，用内容营销换分发渠道。**

## 2. 目标用户画像（ICP）

### 首要 ICP：中国独立开发者做 AI SaaS 出海

- 技术栈偏好 Next.js + TypeScript
- 需要海外收款但没有公司主体（Creem MoR 是刚需）
- 产品形态是 AI wrapper / AI 工具（积分计费是刚需）
- 英语可以读写但更习惯中文文档
- 预算敏感但愿意为省时间付费（$99–$199 是可接受范围）
- 活跃在即刻 / 知乎 / Twitter / Product Hunt

### 次要 ICP：任何想要 MoR 支付的独立开发者

- 不限于中国，任何没有海外公司主体的独立开发者
- 被 Stripe 要求公司主体劝退过
- 需要"一个模板搞定全部基础设施"
- 对 Creem 已有认知

### 反 ICP（不服务）

- **需要多租户的团队/企业**（v1 明确不做，不要在这类用户上浪费营销）
- **已有 Stripe 账号和海外主体的开发者**（他们不需要 MoR 这一层，除非被积分和获客吸引）
- **非 AI SaaS 场景**（纯订阅制 SaaS 不需要积分系统，我们的优势用不上）

## 3. 定价策略

### 定价原则

- 功能比 $199 档的 ShipFast 多（积分、获客、设计系统、i18n），但信任度为零
- 不能高于 $349 的 MakerKit（多租户比我们完整，维护历史长 3 年）
- 不能低于 $49 的 ZapStart（功能远超那个档位，低价反而信号"质量差"）

### 建议方案

| 阶段                 | 价格      | 目标                                             |
| -------------------- | --------- | ------------------------------------------------ |
| **上线首月（早鸟）** | **$99**   | 获取 20–50 个付费用户，积累 testimonials 和案例  |
| **正常售价**         | **$169**  | 稳定跑几个月，验证转化率和用户质量               |
| **后续调整**         | $149–$199 | 根据 feedback 和功能增量（多租户、更多模型）上调 |

### 为什么不是 $199+？

ShipFast 的 $199 靠的是 8400+ 用户、135K 推特的信任背书。我们没有。$99 的早鸟价承认了这一差距，同时给出一个"趁现在便宜"的行动理由。提到 $169 后仍然比 ShipFast 便宜，功能更多——这对理性买家是明确的性价比信号。

### 为什么不是 $49？

ZapStart $49 是"基础功能骨架"的定位。我们的功能深度（积分账本、获客、品牌系统）远超那个档位。低到 $49 会吸引只想便宜、不看重功能深度的用户——他们会是售后负担（"为什么没多租户？为什么没有 XX 模型？"）。

## 4. 分发渠道

没有个人品牌（不像 Marc Lou），分发必须靠**渠道合作 + 内容营销**。

### 渠道 1：Creem 合作伙伴

**这是最高杠杆的分发路径。** Creem 作为 MoR 平台，天然希望有更多模板/教程降低他们的接入门槛。我们的模板让开发者"不用写 Creem 集成"——这对 Creem 的获客有利。

具体做法：

- 联系 Creem 的开发者关系 / partnership 团队
- 争取进入 Creem 官方文档的 "Starter Kits" / "Templates" 区块
- 如果 Creem 有 affiliate 计划，加入
- 写 Creem 接入教程，被 Creem 官方转发

### 渠道 2：内容营销（出海教程）

**不卖模板，卖知识。** 模板是知识付费的自然延伸。

内容主线：

- "独立开发者出海 SaaS 从 0 到 1"系列（技术选型、收款、税务、获客）
- "不需要海外公司也能收美金——Creem 实战指南"
- "AI SaaS 的积分计费怎么设计——从账本到原子扣减"
- 每篇结尾自然提及模板，"不想从零写？这里有完整实现"

分发平台优先级：知乎 > 即刻 > Twitter/X > 小红书（技术内容更适合前两个）

### 渠道 3：Product Hunt

ShipFast 的早期 traction 很大程度上来自 Product Hunt。我们需要：

- 准备好的 PH 上线素材（首图、描述、Maker 故事）
- 在 PH 活跃社区预热 2–4 周
- 选一个周二/周三/周四上线（PH 流量最大的日子）
- 标题突出差异化："Creem-first Next.js SaaS Kit — built-in credits, acquisition & branding"

### 渠道 4：开源引流

模板本身是专有授权，但可以开源一些独立组件：

- `brand-css` 推导逻辑 → 独立 npm 包 / 博文（"一个 hex 换整套品牌色"）
- 积分账本设计 → 架构博文
- 获客归因系统 → 独立指南

这些内容本身有价值，同时把读者引向完整模板。

## 6. 消息框架（Messaging）

### 一句话定位

> **The complete operating system for your AI SaaS.** Payments handled by Creem (no company entity needed). Usage billing via built-in credit ledger. User acquisition tools included. One hex code rebrands the entire site.

### 三大卖点（按买家决策顺序）

1. **"今天 fork，明天收钱"**——Creem MoR 让你不需要海外公司就能收美金。这是 出海开发者的第一痛点。
2. **"AI 调用按次收费，不用自己写"**——积分账本、预扣/退回、幂等 webhook，全部内置。这是 AI SaaS 的基础设施，多数模板没有。
3. **"不只是启动，是持续运营"**——渠道归因、候补名单、邀请奖励。别人卖的是 Day 1，我们卖的是 Day 1–30。

### 对标说法（买家问"和 ShipFast 有什么区别？"）

> ShipFast 帮你更快启动。我们帮你更快启动**并且**更快开始赚钱——积分计费让你第一天就能对 AI 调用收费，Creem 让你不需要海外公司就能收美金。如果你只做订阅制 SaaS、已经有 Stripe 账号，ShipFast 可能更适合你。如果你是 AI SaaS、需要用量计费、没有海外主体——这个组合在抽查过的产品里不多见，值得比一比。

（**不要用「我们是唯一的选择」**：这是我们抽查范围内的结论，不是市场事实，写出去经不起举证。）

| 风险                        | 概率 | 缓解                                                                                                       |
| --------------------------- | ---- | ---------------------------------------------------------------------------------------------------------- |
| **Creem 审核卡住买家**      | 高   | Creem 审核指南文档 + 演示站作为"审核用参考"                                                                |

| **大厂/知名模板跟进 Creem** | 中   | 快速积累用户和 testimonials，用先发优势 + 功能深度建护城河                                                 |

## 8. 不做的事

- **不和 ShipFast 打价格战**。他们在 $199 有 8400+ 用户，我们在 $99 有零。价格战我们只会亏更多。
- **不追求"所有人都能用的模板"**。ICP 窄是好事——功能深度来自聚焦，不是泛化。
- **不做付费广告（v1）**。没有 conversion data 之前，广告预算 = 烧钱。先靠内容营销和渠道合作积累数据。
- **不在 Product Hunt 之前做大规模宣传**。PH 是信任放大器，但前提是已经有 demo、有 testimonials、有文档——先准备这些。
- **不承诺"终身更新"**。MakerKit 可以承诺因为维护了 3 年。我们可以在早鸟期承诺 1 年免费更新，后续定价再调整。

## 9. 时间线建议

2026-09-29 起换成「先能交付，再谈增长」的三周计划（[阶段 23](tasks/phase-23-delivery.md)），原先按周划分的准备期/早鸟期/稳定期在拿到首批买家数据之前都是估算。**不设外部试用**（2026-09-30 定）：模板交付不可回收，首批买家就是正式买家，验证全部在首单交付前做完：

| 阶段                           | 时间     | 目标                                                                                        |
| ------------------------------ | -------- | ------------------------------------------------------------------------------------------- |
| **阶段 A：交付基础**           | 3–4 天   | 买家能升级（T2301）、买家 agent 有指引（T2302）。不通过就不承诺「支持持续升级」             |
| **阶段 B：收费业务的恢复能力** | 5–7 天   | AI 任务不悬挂、计费异常可查可处理、事务邮件可补发（T2303–T2305）                            |
| **阶段 C：真实交付**           | 3–4 天   | 作者按买家路径自验（T2306）、候选发行包（T2307）、首单放行（T2308）。不通过就不交付第一份包 |
| **正式售卖 → 早鸟期**          | 上线首月 | $99 早鸟价，收集反馈与 testimonials                                                         |
| **评估期**                     | 第 4 月  | 用真实数据重估：定价、ICP、要不要继续投功能                                                 |

**放行条件（五条，首单交付前逐条确认，见 T2308）**：升级路径跑通；AI 异常不会无限期悬挂且无人发现；异常退款可查可处理；发行版本 / 许可 / 交付权益 / 支持范围清楚；作者按买家路径、仅凭发行包完成全流程的记录。放行前生产环境用 `SITE_HIDDEN_PLANS` 关掉购买入口。
