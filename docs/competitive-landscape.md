# 竞争格局

状态：2026-09-27 初稿；2026-09-29 按当前实现修正事实（三个支付适配器、升级路径仍待兑现）并删去无证据结论。

本文件记录 SaaS 模板市场的竞争态势，以及本模板相对于现有产品的差异定位。市场变化快，价格和功能请以各产品官网为准。**下文所有「竞品没有 X」都是 2026-09-26/27 抽查官网得出的结论，不是市场普查** —— 抽样覆盖不到的产品、之后上架的产品都可能推翻它；对外表达时按「我们抽查过的产品里」的口径说。

## 市场概览

SaaS 模板/脚手架市场已相当拥挤，Next.js 生态内有 **20+ 个可选项**，大致分三层：

| 层级     | 代表                                                           | 价格      | 典型买家                |
| -------- | -------------------------------------------------------------- | --------- | ----------------------- |
| 免费开源 | Vercel sub-payments、create-t3-app、Open SaaS、next-enterprise | $0        | 愿意自己拼的开发者      |
| 商业低价 | ZapStart、ShipFast、NextBase、BuilderKit                       | $49–$299  | 独立开发者做 MVP        |
| 商业高价 | MakerKit、SaasRock、MuseMVP、Nexty                             | $249–$499 | 要生产级基础的企业/团队 |

## 本模板的差异定位

### 一句话

> **出海 AI SaaS 的完整基础设施——Creem 收款 + 积分计费 + 获客工具 + 一键换品牌，从 fork 到线上收款 ≤ 1 天**

### 独特差异点

在我们 2026-09-26 抽查过的产品里，没有同时具备下面这些的组合（抽查范围与方法见上）：

#### 1. Creem 作为一等支付公民（不是 Stripe）

**这是最大的差异。** 几乎所有竞品都以 Stripe 为主支付。少数加了 Creem（MuseMVP、MkSaaS、Nexty）但仍是 Stripe 优先，或作为中国市场补充。

本模板 **Creem-first**：

- **无需海外公司主体**。Creem 是 Merchant of Record，作为法律卖方替买家处理全球税务合规。Stripe 要求有美国/欧洲公司主体——这是 出海独立开发者的核心痛点。
- 同时提供 Stripe 与 Lemon Squeezy 适配器（`PaymentProvider` 接口，T1801 / T1802）：需要自建主体或已有账号的买家可以换，不必自己写。三个适配器的**真实测试环境验证结果**仍待补（阶段 23 的 T2306 / T2307）。
- 买的不是一个"支付集成"，是一个**不需要海外公司就能收款的 SaaS**。

#### 2. 积分 / 用量计费系统

**抽查的多数竞品不做内置积分账本。** ShipFast、NextBase、SaasRock、MakerKit 都只管订阅/一次性付款，AI 调用的按次计费需要买家自己写（MkSaaS 也有积分，但实现口径我们没核对）。

本模板内置：

- Postgres 账本：`credit_transactions` 记流水 + `user_credits.balance` 作余额缓存
- `UPDATE … SET balance = balance - n WHERE balance >= n` 保证原子扣减
- AI 调用前预扣 → 失败退分 → 写入账本并注明原因
- webhook 幂等：`(provider, event_id)` 唯一约束，重复推送不重复发分
- 依赖单向：billing → credits ← ai，credits 不反向调用，无环

#### 3. 获客能力内建

**渠道归因、候补名单、邀请奖励**——这三块是通用获客能力，但现有模板几乎都不做。要么自己写，要么接第三方（Rewardful 等，月费 $25+）。

| 能力     | 首版范围                                                         |
| -------- | ---------------------------------------------------------------- |
| 渠道归因 | 30 天首次来源、UTM/来源域名、注册关联、渠道注册与收入报表        |
| 线索收集 | 邮箱留资/候补名单、确认与撤回、注册关联、后台筛选及 CSV 导出     |
| 邀请奖励 | 专属链接、新用户绑定、首次有效付款给双方积分、退款回收和后台审核 |

#### 4. 视觉系统：单色推导 + 贴纸深度

竞品 UI 的常见批评：**"买了还得自己重做落地页"**（ShipFast、supastarter 都因此被点名）。

本模板的设计系统：

- **一个 hex 换整套品牌**。`site.config.ts` 的 `brand.primaryColor` → 推导 15+ token（primary、edge、text、band、background、chart-1、中性色阶）
- **贴纸表面**：1px 描边 + 同色零模糊硬唇边，不用模糊投影
- **两个语域**：营销面（色带 + 波浪 + 贴纸）vs 产品面/后台（平面面板 + 高密度）
- **375px 不横向溢出**是 e2e 锁死的行为
- 语义色固定不跟品牌走，CTAs 保留原始 hex 不粉彩化

#### 5. Better Auth + 邮箱验证码

多数竞品用 Auth.js/NextAuth 或 Supabase Auth。Better Auth 是新一代选择：

- **邮箱验证码**（6 位数字，5 分钟有效，跨设备输入），不用 magic link——magic link 会被企业邮箱链接扫描器提前消耗
- 参数显式配置（不依赖插件默认值）：验证码长度、有效期、最大尝试次数、重发冷却
- Admin 插件管理角色
- 仅维护一种邮箱登录方式

#### 6. Neon 可分支数据库

多数竞品用 Supabase（NextBase 强依赖 Supabase）或普通 Postgres。Neon 的**数据库可分支**是差异化能力——开发/测试时从生产 fork 一个分支，不影响线上。

#### 7. 模板仓库模型（上游更新）

买了竞品模板后，上游更新靠什么？MakerKit 靠"daily updates + Discord"（手动跟），大多数小模板**根本不更新**。

本模板设计为：

- `src/core/` 套件代码，业务项目不改；业务代码放 `src/features/`、`(app)` 路由、`site.config.ts`、`messages/`
- `UPGRADING.md` 写清楚更新规则；`scripts/core-drift.sh` 能给出冲突报告（手工跑，未接 CI）
- **更新机制本身仍待兑现**：发行包不带 Git 历史，买家仓库与模板没有共同祖先，`git merge upstream/main` 对他们不成立。阶段 23 的 T2301 要用「版本基线 + 差量更新包 + 三路合并」替代它，并用两个真实版本演练。**在 T2301 合入并演练通过之前，这一项对外按「计划中」讲，不要写成已具备。**

### 本模板的劣势与风险

1. **Creem 审核严格**。比 Stripe 更难通过，买家可能卡在审核上——需要文档说明如何准备审核材料。
2. **真实测试环境未验证**。三个适配器（Creem / Stripe / Lemon Squeezy）都有代码和单测，但都还没在各自的测试环境里按买家流程跑一遍并记录结果——阶段 23 的 T2306 / T2307 补。假服务商（`BILLING_PROVIDER=fake`）的 e2e 通过**不算**验证。
3. **买家更新机制未兑现**。见差异点 7：zip 发行包与模板没有共同 Git 历史，当前 `UPGRADING.md` 教的 `git merge` 对买家不成立。在 T2301 之前不要对外承诺「持续更新」。
4. **市场知名度为零**。ShipFast 8400+ 买家、Marc Lou 135K 粉丝；本模板还没发布。
5. **Neon 绑定**。Postgres 标准，但可分支数据库特性是 Neon 专有。买家换 Supabase 或自建 Postgres 需要迁移 Drizzle 连接层。
6. **v1 不做多租户**。MakerKit 的核心卖点就是多租户。需要团队/组织功能的买家要自己写。
7. **单栈 (Node/TypeScript)**。如果买家之后想加 Python 后端或多语言运行时，架构不允许。
8. **中文文档**。降低了中国开发者的门槛，但非中文买家可能够不到。

### 定位空间

抽查到的最近两个竞争者（MuseMVP $99、MkSaaS）各自覆盖了我们能力矩阵的一个子集，**在我们查过的产品里**没有同时做 Creem + 积分 + 获客 + 品牌系统的。

本模板不是在和 ShipFast 竞争"谁的 MVP 更快"。**差异在于：别人卖的是快速启动，我们卖的是启动后也能持续运营的完整底盘**——积分、归因、留资、邀请，不是"第一天"要的，但"第一周"就会碰到。

2026-09-26/27 抽查口径下的结论到此为止。矩阵里的「买家更新机制」仍是 ⏳ 待兑现，三个支付适配器的真实测试环境也还没验证，**在这两项兑现之前，对外沟通按路线图表述，不按能力表述**。
