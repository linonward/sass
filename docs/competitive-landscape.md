# 竞争格局

状态：2026-09-27 初稿；2026-09-29 按当前实现修正事实（三个支付适配器、升级路径仍待兑现）并删去无证据结论；2026-10-01 全量复查竞品官网（NextBase 官网限流，只能引用第三方评测）并按当前实现更新本模板一侧（四家支付、差量升级已落地、恢复能力、OnwardKit $99、随包内容英文化）。复查推翻了初稿的若干 ❌：MakerKit 有 Better Auth 栈、完整 i18n 和博客，SaasRock 有多租户、i18n 和博客，ShipFast 有博客和 Lemon Squeezy，Vercel 的开源模板已归档。

本文件记录 SaaS 模板市场的竞争态势，以及本模板相对于现有产品的差异定位。市场变化快，价格和功能请以各产品官网为准。**下文所有「竞品没有 X」都是 2026-10-01 抽查官网首页得出的结论，不是市场普查** —— 首页没写的功能可能藏在文档里，抽样覆盖不到的产品、之后上架的产品都可能推翻它；对外表达时按「我们抽查过的产品里」的口径说。

## 市场概览

SaaS 模板/脚手架市场已相当拥挤，Next.js 生态内有 **20+ 个可选项**，大致分三层：

| 层级     | 代表                                                          | 价格        | 典型买家                |
| -------- | ------------------------------------------------------------- | ----------- | ----------------------- |
| 免费开源 | create-t3-app、Open SaaS、ixartz Boilerplate、next-enterprise | $0          | 愿意自己拼的开发者      |
| 商业低价 | ZapStart、MuseMVP、NextBase、MkSaaS、ShipFast、BuilderKit     | $49–$299    | 独立开发者做 MVP        |
| 商业高价 | MakerKit、SaasRock、Nexty                                     | $249–$1,999 | 要生产级基础的企业/团队 |

本模板（OnwardKit）标价 **$99 一次性**（T2404），落在商业低价层：与 MuseMVP 创始价、NextBase 入门档持平，比 MkSaaS 低 $30、比 ShipFast 低 $100 —— 价格本身不构成优势。

## 本模板的差异定位

### 一句话

> **出海 AI SaaS 的完整基础设施——MoR 收款（Waffo 默认，Creem 可换）+ 积分计费 + 获客工具 + 一键换品牌，从拿到发行包到线上收款 ≤ 1 天**

### 独特差异点

在我们抽查过的产品里，没有同时具备下面这些的组合（抽查范围与方法见上）。2026-10-01 复查后，**单项上已经不独有的**是：多支付商可换、Waffo 接入（MuseMVP、MkSaaS 都有）、Better Auth（MkSaaS、MakerKit 也用）、候补名单（MkSaaS 有）、买家能持续收到更新（MakerKit、ShipFast 走 git 仓库访问本来就能）。真正还拉开距离的是 2、3、4、8 这几项。

#### 1. MoR 作为一等支付公民（不是 Stripe）

几乎所有竞品都以 Stripe 为主支付。加了 MoR 的少数几家（MuseMVP：Creem / Dodo / Waffo；MkSaaS：Creem / Waffo；Nexty）把它当成 Stripe 之外的可选项。

本模板 **MoR-first**：

- **无需海外公司主体**。Creem 与 Waffo Pancake 都是 Merchant of Record，作为法律卖方替买家处理全球税务合规。Stripe 要求有美国/欧洲公司主体——这是出海独立开发者的核心痛点。
- 出厂默认是 **Waffo Pancake**（T2327，此前是 Creem）。四个适配器共用 `PaymentProvider` 接口：Waffo Pancake（T2309）、Creem、Stripe、Lemon Squeezy（T1801 / T1802）。法律页按生效的支付商写名称与 MoR 角色（T2404）。
- 「多家可换」本身已不是差异 —— MkSaaS 同样是 `PaymentProvider` 接口。差异在默认路径：README、上线指南、法律页都按 MoR 写，Stripe 是备选。
- **真实测试环境验证仍待补**：T2319 正在 production 上用真实服务逐项验证，四家里 Waffo 必须验证（T2307）。

#### 2. 积分 / 用量计费系统

**抽查的多数竞品不做内置积分账本。** ShipFast、NextBase、ZapStart、MuseMVP 只管订阅/一次性付款；MakerKit、SaasRock 的用量计费走 Stripe metered，是按账期向 Stripe 报用量，不是预付积分。AI 调用按次扣减的账本需要买家自己写（MkSaaS 初稿记为有积分，复查没找到说明，口径未核对）。

本模板内置：

- Postgres 账本：`credit_transactions` 记流水 + `user_credits.balance` 作余额缓存
- `UPDATE … SET balance = balance - n WHERE balance >= n` 保证原子扣减
- AI 调用前预扣 → 失败退分 → 写入账本并注明原因
- webhook 幂等：`(provider, event_id)` 唯一约束，重复推送不重复发分
- 依赖单向：billing → credits ← ai，credits 不反向调用，无环

#### 3. 获客能力内建

**渠道归因、候补名单、邀请奖励**——这三块是通用获客能力，现有模板要么不做，要么接第三方（MkSaaS 的联盟营销走 Affonso / PromoteKit，Rewardful 等月费 $25+）。本模板三块都在自己的库里，不依赖外部服务：

| 能力     | 首版范围                                                         |
| -------- | ---------------------------------------------------------------- |
| 渠道归因 | 30 天首次来源、UTM/来源域名、注册关联、渠道注册与收入报表        |
| 线索收集 | 邮箱留资/候补名单、确认与撤回、注册关联、后台筛选及 CSV 导出     |
| 邀请奖励 | 专属链接、新用户绑定、首次有效付款给双方积分、退款回收和后台审核 |

联盟营销（给推广者分佣）和用户间邀请奖励是两件事：前者是 MkSaaS 的路线，本模板做的是后者，奖励直接落在积分账本里。

#### 4. 视觉系统：单色推导 + 贴纸深度

竞品 UI 的常见批评：**"买了还得自己重做落地页"**（ShipFast、supastarter 都因此被点名）。

本模板的设计系统：

- **一个 hex 换整套品牌**。`site.config.ts` 的 `brand.primaryColor` → 推导 15+ token（primary、edge、text、band、background、chart-1、中性色阶）
- **贴纸表面**：1px 描边 + 同色零模糊硬唇边，不用模糊投影
- **两个语域**：营销面（色带 + 波浪 + 贴纸）vs 产品面/后台（平面面板 + 高密度）
- **375px 不横向溢出**是 e2e 锁死的行为
- 语义色固定不跟品牌走，CTAs 保留原始 hex 不粉彩化
- 默认出一个产品首页（OnwardKit 销售页只是叠加层），表单、列表、确认操作、上传控件是 `src/core/ui/` 的统一组件（阶段 25）

#### 5. Better Auth + 邮箱验证码

多数竞品用 Auth.js/NextAuth 或 Supabase Auth。Better Auth 本身已不独有（MkSaaS 用，MakerKit 三套栈里两套用），差异在默认登录方式和账户安全：

- **邮箱验证码**（6 位数字，5 分钟有效，跨设备输入），不用 magic link——magic link 会被企业邮箱链接扫描器提前消耗
- 参数显式配置（不依赖插件默认值）：验证码长度、有效期、最大尝试次数、重发冷却
- 设置页可改邮箱、管理登录设备，改邮箱后作废全部 session（T1703 / T2505）
- Google 登录 + One Tap；Admin 插件管理角色

#### 6. Neon 可分支数据库

多数竞品用 Supabase（NextBase 强依赖 Supabase）或普通 Postgres。Neon 的**数据库可分支**是差异化能力——开发/测试时从生产 fork 一个分支，不影响线上；升级脚本遇到双方迁移冲突时，也指导买家在 Neon 分支上验证。

#### 7. 买家更新机制（差量更新包）

这一项是**补齐**，不是领先：MakerKit、ShipFast 给买家开 git 仓库访问，买家本来就能 `git merge` 上游（MakerKit 持续更新，ShipFast 官网显示 8 个月前更新）。本模板按 zip 交付，买家与模板没有共同 Git 历史，`git merge` 硬合会把整棵模板树和 add/add 冲突带进来 —— 差量更新包解决的是 zip 交付自己带来的问题。相对仓库访问的好处是更新包不带卖家内部文档、迁移冲突整块停下，但这算不上卖点。

本模板（T2301 已合入）：

- 发行包带 `template.json` 版本基线（版本、提交、每个随包文件的 sha256）
- `scripts/release-package.sh --update <from> <to>` 出差量更新包，`scripts/apply-template-update.sh` 在买家仓库逐文件三路合并：没动过取新版，两边都改自动合并或留冲突标记，`drizzle/**` 两边都动过整块停下，**绝不静默覆盖**；冲突没处理完版本基线不推进
- 更新包零命中内部文档、卖家域名与任务编号
- 已在两个全新买家仓库上演练（干净升级 + 冲突/迁移/删除）。**首个正式版本之间的演练**（`rc.1 → rc.2`，在 T2306 的产品仓库上跑）归 T2307，通过前对外说「支持差量更新」可以，说「已为 N 个版本提供更新」不行。

#### 8. 收费业务的恢复能力

模板通常只覆盖顺利路径。本模板把收费业务出错后的收尾做进了底盘（阶段 23 批次 B）：

- **AI 任务恢复扫描**（T2303）：cron + 机会式扫描，悬着的任务按结果补完或退分
- **计费异常台**（T2304）：差额单、AI 待核对集中到后台，处理留审计
- **事务邮件 outbox**（T2305）：发送失败可补发，不因一次投递失败丢邮件
- **卖可下载文件**（T2405）：付款后经 outbox 发下载链接、站内按授权下载、全额退款收回授权

抽查的竞品官网都没把这类能力列为卖点（未逐一核对实现）。

### 本模板的劣势与风险

1. **MoR 审核严格**。Creem / Waffo 比 Stripe 更难通过，买家可能卡在审核上——需要文档说明如何准备审核材料。
2. **出厂默认商只适合大陆卖家**。Waffo 目前只能人民币提现到中国大陆银行卡 / 支付宝，大陆以外的买家拿到模板后必须先换成 Creem / Stripe / Lemon Squeezy 才能收款。文档在选型处写明了，但对海外买家来说，「开箱即用的收款」这句话不成立；对外文案要么按受众分开讲，要么不把默认商当卖点。
3. **真实测试环境未验证完**。四个适配器（Creem / Stripe / Lemon Squeezy / Waffo）都有代码和单测；T2319 正在 production 上逐项验证，T2306 / T2307 按买家路径再走一遍并记录结果。假服务商（`BILLING_PROVIDER=fake`）的 e2e 通过**不算**验证。
4. **升级通道只在演练仓库里跑过**。差量更新包已落地（见差异点 7），但还没在真实的正式版本之间跑过 —— T2307 的 `rc.1 → rc.2` 演练通过前，不对外承诺更新频率。
5. **市场知名度为零**。ShipFast 8400+ 买家、Marc Lou 135K 粉丝；本模板还没发布。
6. **最近的竞品在追**。MkSaaS 与本模板同为 Better Auth + Drizzle + Creem + Waffo，价格只高 $30；MuseMVP 创始价同为 $99，也有 Waffo 和 i18n。MakerKit 也提供 Drizzle + Better Auth 栈，且有完整 i18n 和博客。单靠「出海 + MoR」或「现代栈」已经讲不出差异，要靠积分、获客、恢复能力和品牌系统这几项的组合。
7. **Neon 绑定**。Postgres 标准，但可分支数据库特性是 Neon 专有。买家换 Supabase 或自建 Postgres 需要迁移 Drizzle 连接层。
8. **v1 不做多租户**。MakerKit 的核心卖点就是多租户，SaasRock 也做。需要团队/组织功能的买家要自己写。
9. **单栈 (Node/TypeScript)**。如果买家之后想加 Python 后端或多语言运行时，架构不允许。

### 定位空间

抽查到的最近两个竞争者是 MuseMVP（$99 创始价 → $228）和 MkSaaS（$129）。2026-10-01 复查后，它们在支付层（多 MoR 可换）和认证层（MkSaaS 的 Better Auth）已经与本模板重合，**在我们查过的产品里**仍没有同时做内置积分账本 + 内置归因/邀请 + 单色品牌系统 + 收费恢复的。

本模板不是在和 ShipFast 竞争"谁的 MVP 更快"。**差异在于：别人卖的是快速启动，我们卖的是启动后也能持续运营的完整底盘**——积分、归因、留资、邀请、出错后的收尾、模板本身的后续更新，不是"第一天"要的，但"第一周"就会碰到。对外文案应把重心从「Creem / 无需海外主体」移到这条运营底盘上：前者竞品已经能讲，后者还讲不了。

结论以上述抽查口径为准。四家支付商的真实测试环境验证（T2319 / T2307）和正式版本间的升级演练（T2307）完成之前，**这两项对外按路线图表述，不按能力表述**。
