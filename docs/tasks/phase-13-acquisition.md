# 阶段 13：获客

状态：T1301 渠道归因基础、T1302 渠道报表、T1303 邮箱留资已实现，其余功能待实施（2026-09-27）。

用户确认将渠道归因、线索收集、邀请奖励三块纳入模板规划。阶段完成后：运营者能知道哪些渠道带来注册和收入，收集并管理尚未注册的意向用户，让已有用户通过邀请获得积分奖励。

本阶段采用以下首版默认范围；各任务分别开分支、worktree、PR，依赖合入 main 后才开工。T1300 为规划任务；各实施任务状态见总表。

## 范围与共用规则

- **渠道归因**：UTM、外部来源域名、首次来源；关联注册用户，在后台按渠道看注册、付费人数和收入。
- **线索收集**：可嵌入的邮箱留资表单、候补名单页面、邮箱确认、撤回、后台筛选与 CSV 导出。
- **邀请奖励**：登录用户专属链接、新用户绑定邀请人、首次有效付款后给双方发积分、退款回收、奖励记录与管理。
- 不做广告投放、广告平台回传、多触点归因、跨设备匿名追踪、CRM 同步、群发营销邮件、自动邮件培育、现金佣金或提现、多级分销。
- 复用 TypeScript + Node、Postgres、现有认证、邮件、积分和计费钩子；首版不新增外部服务、SDK 或运行时。实施中确需新增依赖时先查官方最新稳定版。
- 通用能力位于 `src/core/acquisition/`；数据库定义按现有 schema 目录组织；业务侧在 `site.config.ts`、文案与页面组合处配置活动、奖励和表单。不得在 core 硬编码某个产品的获客规则。
- 配置新增 `acquisition`，其中 `attribution.enabled`、`leads.enabled`、`referrals.enabled` 默认均为 `false`，彼此可独立使用；后台页面另外受 `features.admin` 控制。邀请模块要求 `features.credits`，开启但依赖缺失时配置校验报错。
- 归因和邀请共用入口上下文工具，但各自捕获逻辑受自己的开关控制：关闭归因不影响邀请绑定；全部关闭时不写获客 Cookie、不加载获客客户端脚本、不增加登录/支付链路写入，入口和接口返回 404。
- 新增迁移保持旧数据可用：旧用户来源为 unknown；已有账号不能补绑邀请；不向历史订单补发奖励。开关关闭保留已有数据，停止新增捕获与奖励资格；对已经发放的奖励仍执行退款回收。
- UI 实施先读 `docs/design.md`，沿用配置色、贴纸描边和硬唇边；所有新增文案进入语言文件。

## 数据与统计口径

- 归因默认 30 天窗口、first-touch：首次有效上下文保留至过期，直接回访不覆盖；到期后从下一次有效访问重新开始。只存白名单 UTM 字段、外部来源 hostname、落地 pathname、时间，不存完整 URL、查询串、IP 或设备指纹。字段长度及字符校验在服务端执行。
- 匿名持久化使用有版本的服务端校验上下文；在访客明确允许来源记录后才写第一方 Cookie（30 天、HttpOnly、SameSite=Lax，生产 Secure）。T1301 提供最小的接受/拒绝/撤回入口，不接管现有 Vercel Analytics。拒绝、缺失或过期时记 unknown，不把缺失数据伪装成 direct。Cookie 与相关用途在隐私文案中说明；具体站点上线前按其受众检查配置和文案。
- 有效上下文中按 `utm_source` 优先、外部 hostname 次之、确实无来源时 direct 分组；UTM medium/campaign 用于进一步筛选。OAuth、One Tap、邮箱验证码首次注册均冻结同一份来源快照，老用户登录不改写；跨设备无法关联时保留 unknown。
- 线索确认后保留提交时来源快照；首次注册时仅按已验证邮箱关联线索。用户已有有效获客上下文优先，否则可继承仍在 30 天窗口内的已确认线索来源；过期线索仍可关联但不改变归因。撤回、未确认线索均不能贡献来源。
- 报表用 UTC 半开时间区间、7 / 30 / 90 天：注册数按注册时间；付费人数按区间内成功付款用户去重；收入按区间内成功付款订单金额减这些订单截至查询时的累计退款额，按币种分别展示。说明这是订单归属期净收入，历史区间会随退款变化；退款先到、订单未补齐时单列待核对金额。按用户冻结来源分组，不推断广告花费或 CAC。
- 首版不自建访问量统计，不拿 Vercel 的浏览量当这里的漏斗分母。线索转注册率按“区间内确认的线索，截至查询时已关联注册的比例”计算；付费人数/注册数来自不同时间人群，不能直接标为注册付费转化率。

1. T1300 合入后做 T1301；渠道报表 T1302 需等待 T1202 合入。
2. 完成 T1303 → T1304，获得线索捕获与管理闭环。
3. 完成 T1305 → T1306；奖励结算需等待 T1202、T1204，不能仅凭任务卡存在就开工。

每个实现 PR 跑适用的 lint、typecheck、`pnpm test`；UI 改动至少跑 `npx playwright test e2e/ui-shell.spec.ts e2e/landing.spec.ts`，再跑新增功能的相关 e2e。移动端验收为 375px 无横向溢出，可访问名和键盘操作正确。

最终用一条带 UTM 的邀请链接验收：访客接受来源记录和邀请 → 留资 → 邮箱确认 → 注册 → 首次付款 → 双方积分到账 → 退款回收。分别核对渠道报表、线索关联、邀请关系与积分流水；关掉三块再跑原注册/支付流程，行为应与现有模板一致。
