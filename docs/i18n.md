# 多语言

基于 [next-intl](https://next-intl.dev)。路由在 `src/app/[locale]/` 下，默认语言不带前缀（`/pricing`），其他语言带前缀（`/zh/pricing`）。

## 新增一门语言

以中文 `zh` 为例，不需要改代码：

1. 在 `src/core/i18n/locales.ts` 的 `locales` 里加上 `"zh"`：

   ```ts
   export const locales = ["en", "zh"];
   ```

   （语言清单放在这个文件而不是 `site.config.ts`，是有原因的：客户端组件会经 `core/i18n/navigation.ts` 引用 `routing.ts`，而 `site.config.ts` 走 zod 校验，放在那里会把整个配置 schema 拖进每一个页面的客户端 bundle。`site.config.ts` 从这个小文件读取，所以它仍是唯一来源。详见该文件的注释。）

2. 复制 `messages/en.json` 为 `messages/zh.json`，翻译其中的值，key 保持不变。
3. 运行 `pnpm test`，确认 `messages/zh.json` 与 `en.json` 的 key 一致。
4. 运行 `pnpm dev`，打开 `/zh` 检查页面。

有两门及以上语言时，Header 会出现语言切换器。

语言代码按 BCP 47 书写（`zh`、`zh-TW`、`pt-BR`）。切换器里显示的是该语言的自称（中文、Deutsch），由浏览器的 `Intl.DisplayNames` 生成。

## 浏览器语言

访问**不带前缀**的地址（`/`、`/pricing`、`/blog/xxx`）时，语言按这个顺序决定（`localeDetection`，配置在 `src/core/i18n/routing.ts`）：

1. 地址里的 Language 前缀 —— `/zh/pricing` 永远是中文，不会被改写
2. 语言 cookie —— 用户**主动切换**过语言
3. `Accept-Language` —— 浏览器语言，支持的多语言里匹配不到就落到第 4 条
4. 默认语言

匹配上第 3 条时返回 307 到带前缀的地址（`/` → `/zh`，`/pricing` → `/zh/pricing`）。**是 307 不是 301/308**：语言偏好会变，永久跳转会被浏览器和搜索引擎记住，改不回来。跳转响应带 `Vary: Accept-Language`，免得 CDN 把中文访客的跳转缓存下来发给英文访客（只有跳转带得上这个头：Next 会重建 200 响应的 `Vary`；200 的正文本来就跟浏览器语言无关，不带前缀的 200 就是默认语言的页面）。

**只有主动切换才被记住。** 点开一条 `/zh` 分享链接**不写** cookie —— 否则英文访客点错一次，之后每次访问 `/` 都被送去中文站。写 cookie 的只有语言切换器（`src/core/i18n/locale-switcher.tsx`，Header 和后台用户菜单共用它）；next-intl 的中间件本来会在「访问了带前缀的地址」时自己写一个，`src/proxy.ts` 会把它删掉。

不想要自动跳转就把它关掉（比如面向多语言站但不希望 URL 被改写时），改 `src/core/i18n/routing.ts`：

```ts
localeDetection: false,
```

关掉后：cookie 与 `Accept-Language` 都不再参与，`/` 永远是默认语言，语言只由地址前缀和切换器决定。

### SEO

自动跳转不影响 Google 抓取：Googlebot [不发 `Accept-Language`](https://developers.google.com/search/docs/specialty/international/locale-adaptive-pages)，拿到的永远是默认语言版本。反过来说，Google 也**不会**通过跳转发现 `/zh` —— 各语言版本靠 sitemap 里的 `<xhtml:link rel="alternate" hreflang>` 与页面里的 hreflang 互相声明（`e2e/i18n/seo.spec.ts` 锁着）。所以**新增一门语言后要确认 sitemap 与 hreflang 带上了它**，那才是收录的入口。

## 改默认语言

把 `src/core/i18n/locales.ts` 里的 `defaultLocale` 改成另一个已在 `locales` 里的语言。改完后，原默认语言的地址会带上前缀。

## 文案

- 所有界面文案放在 `messages/<locale>.json`，以 `en.json` 为准做类型检查：`t("...")` 写错 key 时，`pnpm typecheck` 会报错。
- `site.config.ts` 里的导航项（`nav.header`、`nav.footer`）写的是 `Nav` 下的 key，不直接写文案。
- 站内链接用 `@/core/i18n/navigation` 导出的 `Link`，会自动带上当前语言前缀。
- 博客文章按语言放在 `content/blog/<locale>/`，不会自动回退到默认语言。新语言没有文章时 `/zh/blog` 是空列表（noindex）；翻译某篇文章时用和原文相同的文件名，hreflang 会把两者关联起来。

## 测试

`pnpm test:e2e` 里的 `i18n` project 会在临时目录复制一份仓库，按上面的步骤加入测试语言 `de`（文案由 `en.json` 自动生成，带 `[de]` 前缀），再构建并启动，验证语言切换、URL、文案、以及上面那条自动检测的优先级（`e2e/i18n/detection.spec.ts`）。见 `e2e/i18n/serve.ts`。
